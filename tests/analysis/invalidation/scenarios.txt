# The scenarios of the invalidation oracle (tests/invalidation.sh; docs/TARGETS.md, "The
# invalidation oracle"): per scenario a case of modules (`a`, `b`, ...: each a project over the
# ones before it), an edit, and what it must do.
#
#   scenario <name>              the case is tests/analysis/invalidation/<name> unless
#     fixture <dir>              names another directory under tests/
#     modules <m>...             the projects in their order (the case's a, b, c, main by default;
#                                none: the case's directory is one project)
#     pad <n>                    n sources of their own per project, apart from the case's, so
#                                that an edit stays under zinc's recompileAllFraction
#     jar <lib>                  the case's <lib>/ compiled by scalac into a jar on every
#                                project's class path
#     variant <name> <opt=v>...  a run of its own with zinc's options (transitiveStep,
#                                recompileAllFraction, useOptimizedSealed; zinc's defaults
#                                otherwise); one `default` run without any variant line
#     edit replace <path> [<from>]
#                                <path> takes the text of the case's edit/<path>, or of <from>
#     edit add <path>            the same, a source the case has not
#     edit remove <path>         the source removed
#     edit touch <path>          the source written again with the same text
#     edit delete-product <m> <class file>
#     edit replace-product <m> <class file> <other class file>
#                                in both sides' class directories of project <m>
#     edit replace-jar <lib>     the jar built again from the case's edit/<lib>/
#     edit before <m> <edit>     a product edit applied to each side's class directories after the
#                                runs of the projects before <m>, just before <m>'s
#     teq-check <m>              teq builds project <m> with `teq compiler check --products`: its pickles,
#                                no class files
#     refuse <side> <m>          <side>'s build of <m> before the edit fails, and the side stops
#     status pass | fail <path>...
#                                what the edited case does when built afresh: it compiles, or it
#                                fails with errors in those sources
#     change <text>              the edit in words
#     rule <text>                zinc's rule the scenario exercises
#     obligation <text>          what it checks
#     expect [<side>] compiled <path>...       compiled again by the run (each side, or <side>)
#     expect [<side>] not-compiled <path>...   not compiled again
#     expect [<side>] cycle <n> <path>...      the batch of cycle n of the source's project
#     expect [<side>] change <class> <kind>    an API change zinc detects in a cycle
#     expect [<side>] full <project>           a cycle compiles every source of the project
#     expect [<side>] transitive <project> <path>...
#                                              the cycle at transitiveStep invalidates
#                                              transitively: the next cycle's batch holds every
#                                              source named
#     expect [<side>] event <kind> <class>     an invalidation event outputs the class (the kind's
#                                              words joined by `_`: `local_inheritance`)
#     expect [<side>] recompiled <class>...    a cycle compiles the class again
#     expect [<side>] collision <m>:<product>  a batch reports the product from a source other
#                                              than the one the analysis keeps as its owner
#     expect @<variant> ...                    the expectation of one variant
#     expect <side> refused <m> <text>         the side refused project <m>, its failure saying
#                                              <text> (a word)
#
# The paths are the sources' under the case, `<project>/<file>`.
