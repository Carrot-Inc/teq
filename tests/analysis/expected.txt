# The mappings of tests/analysis.sh: a part of teq's graph that differs from scalac's, for a
# reason docs/TARGETS.md ("The analysis graph", the mappings) states by construction.
#
#   <project> <class> <name> <mapping>     the definitions named <name> in <class> (or the class's
#                                          companion) and the name hash of <name> may differ;
#                                          <header>, <self>, <children>, <parents>, <products>
#                                          name those parts of the class
#   <project> <class> <class> <mapping>    the class, or its companion, is absent from one side
#   <project> <part> <class> <name> <mapping> <side> <fields>
#                                          a dependency of the referring <class> that the callback's
#                                          <part> reports and <side> alone has: the used name <name>
#                                          (usedName; <fields> its scopes), the class <name> depended
#                                          on (classDependency; its context), the binary class <name>
#                                          depended on (binaryDependency; its entry, source and
#                                          context), the fields joined by commas
#   exact <project>                        every class and every dependency matches exactly; no
#                                          mapping applies
#
# A difference no line names fails, and so does a line that names nothing that differs; zinc's
# apiHash and extraHash of a class may differ only where a line names a difference, and a stored
# relation only where a line names a difference of the dependencies it comes from.
#
# The invalidation oracle's lines (tests/invalidation.sh, tests/analysis/invalidation.py), at the
# end of the file:
#
#   inv-status <scenario>/<variant> <project> <side|both> <outcome>
#   inv-batch <scenario>/<variant> <project> <side|both> <cycle> <source,...>
#                                          each side's outcome and batches, frozen
#   inv-diff <scenario>/<variant> <project> <side> <kind> <cycle|-> <source or class> <reason>
#                                          a difference of the sides, or of a side's run and its
#                                          fresh build, named exactly and with its reason

# The invalidation oracle's differences, by reason.

# inline-modifier: teq's inline marker hashes a local definition's modifiers; scalac's tree hash
# leaves the symbols' flags out, so a `lazy` dropped from a local val of an inline body (the
# expansion returns 1 where it returned 0) changes no marker and leaves scalac's caller stale, where
# teq compiles it again.
inv-diff inline-modifier/default a scalac continues 1 False inline-modifier
inv-diff inline-modifier/default a scalac stale - ilm/Caller$.class:differs inline-modifier
inv-diff inline-modifier/default a teq batch 2 a/Caller.scala inline-modifier
inv-diff inline-modifier/default a teq change 1 ilm.Lazy:NamesChange inline-modifier
inv-diff inline-modifier/default a teq continues 1 True inline-modifier
inv-diff inline-modifier/default a teq continues 2 False inline-modifier
inv-diff inline-modifier/default a teq cycle-sources 2 a/Caller.scala inline-modifier
inv-diff inline-modifier/default a teq event 1 inheritance:ilm.Lazy>ilm.Lazy inline-modifier
inv-diff inline-modifier/default a teq event 1 member_reference:ilm.Lazy>ilm.Caller inline-modifier
inv-diff inline-modifier/default a teq invalidated 2 ilm.Caller inline-modifier
inv-diff inline-modifier/default a teq next 1 ilm.Caller inline-modifier
inv-diff inline-modifier/default a teq recompiled 2 ilm.Caller inline-modifier

# inline-resolved: teq's inline marker hashes the member a reference of the body resolves to;
# scalac's tree hash its name alone, so a private val's type changed from Int to Long under an
# unchanged `secret.toInt + 1` (now `Long.toInt`) changes teq's marker of `peek` and not scalac's.
# Both sides compile the caller again through the accessor `inline$secret` the expansion calls.
inv-diff inline-accessor/default a teq names 1 iac.Lib.peek:Default inline-resolved

# zinc-auxiliary: scalac's pickle is an auxiliary file of its class files (sbt's `TastyFiles`), which
# zinc deletes with them and never stamps, so a pickle deleted from the class directory goes
# unnoticed and scalac's side leaves it missing; teq's check registers its pickle as a product of
# the source (from the answer's journal), so teq's side compiles the source again.
