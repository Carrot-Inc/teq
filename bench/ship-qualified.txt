# bench/ship-qualified.txt: what the ship made on Linux publishes (docs/SPEED.md, "The ship from Linux"):
# the toolchain the maintainer's comparison on the reference machine qualified, as the manifests of bench/ship-manifest.sh record it,
# `<tool> <version...>`, and the routes whose binaries have run where they are for, `route <classifier>`.
# integrations/sbt/binary/check.sh refuses a binary whose manifest records another toolchain or whose route
# has no line, and every binary while a `pending` line stands; bench/ship.sh stages such a binary and holds
# it back. rust-toolchain.toml floats on stable, so rustc, LLVM and cargo are the versions it resolved to;
# zig links every binary, qemu-user runs the aarch64 trainer and the Linux aarch64 suite over the sysroot,
# wine the Windows smoke (the tools of each route: bench/ship-release.sh). The file changes by a commit after
# a new comparison on the reference machine, or after a route's binary
# ran where it is for (its line), never to let a build through. `image <reference>` names the release
# workflow's build environment (bench/actions/ship-image.txt), whose binaries every other line must describe;
# once it stands, a binary built elsewhere is not published. A new image's line, with the tuple its binaries
# record, comes in the commit after a dry run of the workflow (.github/workflows/release.yml) in which the
# five binaries built there passed their qualification on their platforms (docs/DEVELOPING.md, "Releases").
